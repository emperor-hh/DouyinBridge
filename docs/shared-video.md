# 分享视频 / 图文卡片接入 (v0.4.0)

## 运行机制

- 与普通聊天共用已授权私聊和群聊的消息拉取，识别上游 `ChatBrowser.readConversation()` 的 `media.type === 'shared-work'`。
- 即使消息没有 `text`，也会转成 OneBot v11 **文本片段**，包含可见标题、作者、作品 ID 和**严格核实**的作品链接。
- 只有 https://www.douyin.com/video/<ID> 且 ID 与卡片一致、无身份冲突时才转发可点击链接；未核实的链接被隐去。
- 区分图文与视频；强制说明「仅卡片元数据，未观看视频或听到声音」。
- 依然需要白名单授权和消息末尾可靠性证据；群聊需要能验证发送成员 ID。首次扫描只建立基线，不会把历史分享重播给 AstrBot。
- 不抓取网络视频、不点击分享卡片、不自动播放。普通文字消息逻辑不变。
- `SHARED_VIDEO_FORWARDING=false` 可全局关闭分享卡片信息转发（需重启）。
- Web 控制台可对每个已识别会话独立开启 **视频卡片封面**（持久化 SQLite、无需重启）。
- 开启封面选项后，私聊新分享将尝试上游 `captureMessage`，群聊仅在该分享消息 `mentionedSelf===true` 时尝试。
- 截图验证为对应分享消息的 JPEG，最大 500 KiB，通过 OneBot `image` 段传给 AstrBot；截图失败仍转发文字元数据。
- **图片只是单张封面，不能用来回答「视频完整内容」**；AstrBot 需要配置能处理图片的模型，且其 OneBot 适配器应兼容 `base64://` 图片段。
- 对话授权被撤销或封面选项被关掉时，不再发送新的截图。已发给 AstrBot 的数据无法撤回。

## Example (synthetic)

```text
[抖音分享视频]
标题：示例标题
作者：示例作者
作品ID：123456789
作品链接：https://www.douyin.com/video/123456789
内容范围：仅已显示的分享卡片元数据，未观看视频或收听音频。
```

## 未完成

真实抖音账号上的端到端测试、视频播放/分时帧采样、音轨转写、真正的多模态视频分析没有在当前版本实现。
今后的「按需视频分析」应要求独立显式触发（如群聊 @机器人 并请求分析视频），依次确认作品 ID、身份与权限，限制每个会话的采样预算及频次。
